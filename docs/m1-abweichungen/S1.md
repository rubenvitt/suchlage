# Abweichungen Task S1

Abweichungen vom Plan `docs/superpowers/plans/2026-10-16-m1-live-lage.md`, Task S1.

## Testhelfer `lookup` in `src/config.rs` kompilierte nicht

Der Plan schreibt `fn lookup(pairs: &[(&str, &str)]) -> impl Fn(&str) -> Option<String> + '_`.
Rust 1.99 lehnt das mit E0106 ab, weil `'_` nicht weiß, von welcher der drei Lebensdauern
die Rückgabe abhängt. Jetzt: `fn lookup<'a>(pairs: &'a [(&'a str, &'a str)]) -> … + 'a`.

## Doku-Kommentar an `BootConfig::public_url`

Der Plan beschreibt das Feld als „ohne abschließenden Schrägstrich“, sein eigener Test erwartet
aber `http://127.0.0.1:8080/`. `url::Url` hängt an eine Adresse ohne Pfad immer `/` an. Der
Kommentar beschreibt jetzt dieses Verhalten; Code und Test sind wie im Plan.

## Tests für `extract::JsonBody`

`testing::post_json` hätte im Plan keinen Aufrufer. `cargo clippy --all-targets -- -D warnings`
bricht dann mit `dead_code` ab. Statt den Helfer zu streichen oder die Warnung zu unterdrücken,
prüfen zwei Tests in `src/extract.rs` den Extractor: Ein gültiger Body erreicht den Handler, ein
abgelehnter antwortet mit 400 und `{"error": "Ungültige Anfrage: …"}`.

## `unknown_api_route_is_json_404` prüft auch den Body

Der Testname verspricht ein JSON-404, der Plan prüfte nur den Status. Der Test erwartet jetzt
zusätzlich `{"error": "Nicht gefunden"}`.

## `scripts/check.sh`: Modulgrenzen-Grep

- `\s` ist eine GNU-Erweiterung, POSIX-ERE kennt sie nicht. Jetzt `[[:space:]]`, damit das Gate
  mit jedem `grep` gleich prüft.
- Der Grep auf `src/situation` läuft nur, wenn der Ordner existiert (wie schon beim `src/dji`-Grep).
  Vorher schrieb das Gate bis Task B3 bei jedem Lauf „No such file or directory“ ins Log.
