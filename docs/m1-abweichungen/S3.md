# Abweichungen Task S3

Abweichungen vom Plan `docs/superpowers/plans/2026-10-16-m1-live-lage.md`, Task S3.

## Kein echter Name im Beispiel `meAdmin`

Der Plan setzt in `contract::examples::all()` für `meAdmin` den Namen einer realen Person ein.
Beispieldaten sind nach den Global Constraints synthetisch, und der Name stünde danach in jeder
Frontend-Vorschau und jedem Screenshot. Jetzt steht dort der Platzhaltername „Erika Mustermann“.

Folge für spätere Tasks: F1 erwartet im Test des Benutzermenüs den Knopf
„Benutzermenü von Ruben Vitt“ (Plan, Task F1). Gegen `meAdmin` heißt er jetzt
„Benutzermenü von Erika Mustermann“, die Initialen im Kopf sind „EM“ statt „RV“.

## Synthetische Workspace-ID im Beispiel `settingsView`

Der Plan setzt als `workspace_id` die echte Pilot-2-Workspace-ID aus M0 ein
(`deploy/pilot/config.tpl.js`). Beispieldaten sollen nichts aus dem Betrieb tragen; jetzt steht
dort `00000000-0000-4000-8000-000000000001`.

## Spec §7: auch die M1-Zeile nennt SSE

Der Plan ändert „WebSocket“ in §3 (Zeichnung und Tabelle) und §6. Die Meilensteintabelle in §7
nannte für M1 ebenfalls „WebSocket“; sie sagt jetzt „SSE“, damit die Spec an keiner Stelle mehr
der ADR 0001 widerspricht. In der Zeichnung steht nur „SSE“ (ohne „ADR 0001“), damit der Kasten
seine Breite behält; die Tabellenzeile verweist auf die ADR.

## `cargo test export_bindings` entfällt als eigener Schritt

ts-rs 12 erzeugt die Typen in Tests namens `contract::…::export_bindings_<typ>`. Der Filter
`cargo test contract` trifft sie bereits, ein zweiter Lauf mit `export_bindings` erzeugt nichts
Neues. Das Gate (`cargo test` ohne Filter) erzeugt beides ohnehin.

## Strang-Branches und Worktrees nicht angelegt

Step 6 legt am Ende `m1-backend` und `m1-frontend` als Branches samt Worktrees an. In diesem
Durchlauf übernimmt die Orchestrierung die Strang-Topologie (Integrations-Branch `m1` statt
`main`); ein vorab angelegter Branch ließe ihr `git worktree add -b` scheitern. Deshalb legt S3
keine Branches und Worktrees an.
